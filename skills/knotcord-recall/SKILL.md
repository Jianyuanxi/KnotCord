# 找回旧信息

KnotCord 记的是"发生过什么"（做过什么、改了什么、为什么）。长期事实（用户偏好、服务器配置、项目约定）以内置记忆文件为准，KnotCord 只补它没有的细节。

## 查找顺序

1. 内置记忆文件：先读 `MEMORY.md` 索引里相关的那几个文件。有答案就停，不再往下查。
2. KnotCord：内置记忆里没有，或要的是"当时怎么做的、中间出过什么错"，用下面三步。
3. 会话原文（`~/.claude/projects/` 下的 transcript）：KnotCord 的条目太简略、需要原话或完整命令输出时才翻，先用 `get` 的 `with_source` 或条目里的会话编号定位，不通读。

## KnotCord 三步检索

工具名是 `mcp__plugin_knotcord_knotcord__search`、`mcp__plugin_knotcord_knotcord__timeline`、`mcp__plugin_knotcord_knotcord__get`。每一步只拿下一步需要的东西，不要一上来取全文。

1. `search`：参数 `query` 写 2 到 4 个关键词（空格分隔，都要命中；结果太少会自动放宽）。可加 `project`（项目名）、`since`/`until`（`7d`、`12h`、`2026-11-01`）、`limit`。返回每条一行：编号 日期 项目 标题。
2. `timeline`：对看起来相关的一条，用它的编号看前后同一会话里发生了什么（`before`、`after` 默认各 3 条），判断是不是要找的那件事。
3. `get`：确认相关后，按编号取全文，可以一次传多个。只取你要用的几条。

## 编号前缀

| 前缀 | 含义 |
|---|---|
| n | 笔记（提炼出的事实、决定、踩的坑） |
| u | 没做完的事 |
| s | 会话总结 |
| p | 用户当时的提示 |
| m | 内置记忆文件（`get` 只返回文件路径，正文自己 Read） |
| e | 原始事件里的某一行 |

## 使用要点

- 搜不到就换关键词再试一次（换说法、换英文或中文），仍没有就如实告诉用户"KnotCord 里没有记录"，不要编。
- 带"已被取代"标记的旧笔记默认不显示；要看演变过程时才设 `include_superseded`。
- 查到的内容可能已过时：涉及文件、版本、服务器状态，先用工具核实现状再据此行动。
- 今天的提炼次数、花费和积压用 `usage` 工具看；本机自查用 `python -I -X utf8 <插件根>\knotcord\boot.py doctor`。
- 不要把检索结果整段转述给用户；只说和当前问题相关的结论和出处编号。
